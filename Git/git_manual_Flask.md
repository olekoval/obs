# 🚀 Шпаргалка з Git для Flask-проекту: Безпечна розробка та відкат

Цей посібник допоможе вам безпечно внести значні зміни у ваш робочий Flask-проект, мінімізуючи ризики та забезпечуючи простий шлях для повернення до початкового стану.

---

## 🎯 Головна стратегія
**Ніколи не пишіть експериментальний код прямо в гілці `main`.** Створення окремої гілки ізолює ваш робочий код. Навіть якщо в новій гілці все зламається, ваш основний сайт (на `main`) залишиться цілим і неушкодженим.

---

## 🛠️ Алгоритм дій: Як впроваджувати зміни

### Крок 1: Створення нової гілки
Переконайтеся, що ви перебуваєте на чистій гілці `main`, і створіть нову гілку (наприклад, `feature-big-changes`):
```bash
git checkout -b feature-big-changes
```
### Крок 2: Розробка та фіксація змін

Пишіть свій код у Flask. Робіть коміти частіше, розділяючи зміни на логічні блоки:
```bash
git add .
git commit -m "Опис змін (наприклад: Оновлено моделі бази даних)"
```

### Крок 3: Резервна копія на GitHub

Щоб ваш прогрес зберігався не лише на комп'ютері, відправте нову гілку в хмару:
```bash
git push -u origin feature-big-changes
```
### Крок 4: Фінал (Якщо все працює ідеально)

Коли ви повністю протестували проект і переконалися, що все працює стабільно, об'єднайте зміни з головною гілкою:
```bash
# 1. Поверніться на головну робочу гілку
git checkout main

# 2. Влийте зміни з нової гілки в main
git merge feature-big-changes

# 2.1. Видалити гілку яка була з'еднана з main
git branch -d feature-big-changes

# 3. Відправте оновлений main на GitHub
git push origin main
```
## 🚨 План порятунку: Варіанти відкату (Якщо все зламалося)

Залежно від ситуації, оберіть один із трьох варіантів повернення до робочого стану.

### Варіант А: Повний відкат експериментів (Ви працювали в новій гілці)

Найкращий сценарій. Оскільки гілка `main` не змінювалася, ми просто видаляємо невдалу гілку та повертаємося до стабільної версії:
```bash
# 1. Поверніться у безпечний main
git checkout main

# 2. Жорстко видаліть зламану гілку на комп'ютері
git branch -D feature-big-changes

# 3. (Опціонально) Видаліть цю гілку з GitHub, якщо встигли туди відправити
git push origin --delete feature-big-changes
```
### Варіант Б: Екстрений відкат (Ви випадково писали код прямо в `main`)

Якщо ви забули створити гілку і зіпсували код прямо в `main`, але на GitHub у вас точно лежить остання чиста робоча версія:
```bash
# УВАГА: Ця команда безповоротно знищить всі ваші останні локальні зміни в main!
git reset --hard origin/main
```
### Варіант В: Точковий відкат (Зламався лише останній коміт у новій гілці)

Якщо ви не хочете видаляти всю нову гілку, а бажаєте просто скасувати один останній коміт, який усе зламав:
```bash
# Спосіб 1: Скасувати коміт, але ЗАЛИШИТИ ваш код у файлах для виправлення помилок
git reset --soft HEAD~1

# Спосіб 2: Скасувати коміт і ПОВНІСТЮ ВИДАЛИТИ ці зміни з файлів (повернення на 1 коміт назад)
git reset --hard HEAD~1
```
💡 **Головне правило:** Поки ваш робочий код лежить на GitHub, а ви експериментуєте в іншій гілці — ваш проект у повній безпеці!
