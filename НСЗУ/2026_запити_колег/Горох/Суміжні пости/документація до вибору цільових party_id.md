# Документація: визначення цільової посади (`position_tg`) для співробітників

## Призначення скрипту

Скрипт визначає **цільову (зведену) посаду** (`position_tg`) для кожного співробітника на основі даних таблиці `core.dim_rpt_employees`. Якщо у співробітника зафіксовано рівно одну унікальну посаду з заданого переліку — повертається саме вона. Якщо посад декілька — встановлюється значення-замінник `'P5'`.

## Вихідні дані

**Джерело:** `core.dim_rpt_employees`

**Умови фільтрації (`WHERE`):**

| Умова | Опис |
|---|---|
| `is_current = 'Y'` | Враховуються лише актуальні (поточні) записи співробітника |
| `is_active = true` | Враховуються лише активні співробітники |
| `kwd_position IN ('P229', 'P231', 'P25', 'P3', 'P5')` | Враховуються лише задані коди посад |

## Логіка обробки

### Крок 1. Підзапит — групування та агрегація

```sql
SELECT legal_entity_id, 
       party_id, 
       string_agg(DISTINCT kwd_position::text, ', ') AS position_target,
       COUNT(DISTINCT kwd_position) AS cnt
  FROM core.dim_rpt_employees
 WHERE is_current = 'Y' 
   AND is_active = true
   AND kwd_position IN ('P229', 'P231', 'P25', 'P3', 'P5')
 GROUP BY legal_entity_id, party_id
```

Для кожної унікальної пари `legal_entity_id` + `party_id` (тобто для кожного співробітника в межах юридичної особи):

- **`position_target`** — список усіх унікальних посад співробітника, об'єднаних у текстовий рядок через кому (`string_agg(DISTINCT ...)`);
- **`cnt`** — кількість унікальних посад у цього співробітника (`COUNT(DISTINCT ...)`).

> Оскільки групи формуються тільки з рядків, що пройшли `WHERE`, значення `cnt` завжди ≥ 1. Випадок `cnt = 0` неможливий — якщо у співробітника немає відповідних записів, рядок для нього в результаті підзапиту просто не з'явиться.

### Крок 2. Зовнішній запит — визначення цільової посади

```sql
SELECT legal_entity_id,
       party_id,
       CASE
           WHEN cnt = 1 THEN position_target
           ELSE 'P5'
       END AS position_tg
  FROM (...) AS t
```

Правило визначення `position_tg`:

| Умова | Результат |
|---|---|
| `cnt = 1` (у співробітника рівно одна унікальна посада) | повертається ця посада (`position_target`) |
| `cnt > 1` (у співробітника декілька різних посад) | повертається фіксоване значення `'P5'` |

## Результат

Підсумкова вибірка містить три поля:

| Поле | Опис |
|---|---|
| `legal_entity_id` | Ідентифікатор юридичної особи |
| `party_id` | Ідентифікатор співробітника |
| `position_tg` | Цільова посада: конкретний код, якщо посада єдина, або `'P5'`, якщо посад декілька |

## Бізнес-логіка (припущення)

Скрипт реалізує правило: **якщо в співробітника одна посада — вона і є цільовою; якщо посад декілька (суміщення) — пріоритет автоматично надається посаді `'P5'`** як умовному дефолтному/об'єднуючому значенню.

> ⚠️ Перед використанням у продакшені варто переконатися, що вибір саме `'P5'` як значення для співробітників із кількома посадами є навмисним бізнес-рішенням, а не випадковістю (оскільки `'P5'` також присутній у вихідному переліку посад `IN (...)`).

## Технічні примітки

- `kwd_position::text` — явне приведення типу до `text`, потрібне якщо `kwd_position` має тип, відмінний від текстового (наприклад, `enum`).
- `DISTINCT` у `string_agg` та `COUNT` гарантує, що повторювані значення посади в межах одного співробітника не впливають на результат.
- Запит не містить `ORDER BY`, тому порядок рядків у результаті не гарантований.
