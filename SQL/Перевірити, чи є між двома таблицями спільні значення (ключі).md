* Використання `EXCEPT` — це один із найпростіших і найшвидших способів перевірити, чи є між двома таблицями **спільні значення (ключі)** для зв'язування через `JOIN`, і які саме значення втрачаються.

  

Діагностику через `EXCEPT` та його аналог `INTERSECT` зручно робити за такими сценаріями:

  

### 1. Пошук ключів, за якими `JOIN` спрацює

Щоб побачити тільки ті значення, які **гарантовано з'єднаються** (є в обох таблицях), використовується оператор `INTERSECT` (перетин):

  

SQL

```
SELECT table_a_key FROM table_a
INTERSECT
SELECT table_b_key FROM table_b;
```

_Результат:_ Список усіх ключів, які поверне `INNER JOIN`.

  

### 2. Перевірка на "незв'язані" записи перед `LEFT JOIN`

Якщо ви плануєте виконувати `table_a LEFT JOIN table_b`, оператор `EXCEPT` покаже, які саме рядки з `table_a` **не знайдуть відповідності** в `table_b` (і отримають `NULL` в останній):

  

SQL

```
SELECT table_a_key FROM table_a
EXCEPT
SELECT table_b_key FROM table_b;
```

_Результат:_ Ключі з першої таблиці, для яких немає пари в другій.

  

### 3. Перевірка "зворотних" втрат перед `FULL OUTER JOIN`

Щоб дізнатися, які ключі є в `table_b`, але відсутні в `table_a`, просто міняємо таблиці місцями:

  

SQL

```
SELECT table_b_key FROM table_b
EXCEPT
SELECT table_a_key FROM table_a;
```

### Чому цей підхід зручний?

1. **Швидка оцінка цілісності даних:** Можна миттєво підрахувати кількість записів, що втрачаються, за допомогою `COUNT`:
    
      
    
    SQL
    
    ```
    SELECT COUNT(*) FROM (
        SELECT table_a_key FROM table_a
        EXCEPT
        SELECT table_b_key FROM table_b
    ) AS missing_keys;
    ```
    
2. **Простий синтаксис:** На відміну від складних `WHERE NOT EXISTS` або `WHERE ... IS NULL`, запит із `EXCEPT` читається максимально прозоро.
    
      
    

> **Важливий нюанс:** `EXCEPT` автоматично робить `DISTINCT`. Якщо у вашій першій таблиці ключ повторювався 10 разів і його немає в другій таблиці, `EXCEPT` поверне лише **один** рядок із цим значенням.
